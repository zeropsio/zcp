# Where answers (`where.go`)

- WG-PART — A paired copy and its stage use the part named by status even when its dev server has another name; a separate dev server remains visible.

- WG-BOUND — A read still unanswered when the bound passes leaves its fact not read and the answer still comes with every fact that was read.
- WG-WIRE — The early envelope snapshot exposes stages before lease reconciliation without changing the envelope tools return.
- WG-STANDING — Where lists only open changes without a working copy, while their standing leaves existing tool JSON unchanged.
- WG-FRESH — A copy's edit step uses HQ's answer to this call; a last-heard change or absence remains unknown.
- WG-HEAD — A detached checkout and an unborn branch say which branch or commit is absent instead of saying the checkout did not answer.
- WG-GROUP — An unread lease does not hide work in another copy, but no copy is handed over until its branch group is read.
- WG-REVIEWSTEP — A fresh HQ Review build result reaches the copy's edit step, so a failure at that head is repaired.
- WG-NOCOPY — An unheld change uses its own repository's classic copy and that copy's fresh handover plan, or a lease for a pool-only repository.
- WG-NOCOPYREAD — When a classic checkout's branch was not read, a change in that repository says its copy is unknown instead of claiming none exists or telling the agent to switch branches.
- WG-OPENBRANCH — Opening a change on a classic pair uses the addressed dev checkout's branch, and never opens from main.
- WG-NEEDCOPY — Describing a branch without a copy names acquiring its pool lease or the classic dev half's occupied or unread handover state.
- WG-DESCRIBEDHEAD — A description is handed over only if the branch-group plan still says the same change and commit are handed over.
- WG-KEPTHEAD — A new describe call binds its supplied words to its addressed commit, even when the same words were kept at another or an empty head; without a new call the words stay at their original head.
- WG-MOVEDSTEP — When HQ refuses a description because its head moved, the kept words stay at their commit and the reply names the branch's next step.
- WG-ACKHEAD — An acknowledgement for one commit cannot discard identical words kept for another commit.
- WG-DESCRIBECOPY — Describing cannot choose arbitrarily between several addressed checkouts.
- WG-REVIEWPROMISE — A handover promises an awaiting Review build only when HQ reports it for that commit.
- WG-POOLADDRESS — A pool handover asks the agent to give the person only the app's durable address and describe work in progress as a draft, keeping temporary addresses out of replies and descriptions.
- WG-OPENREPLY — Opening with a description preserves the open's settled-change and lost-answer notes and whether it was created, alongside the description's answer or refusal.
- WG-OPENSTEP — The open's reply asks for a description only when this call did not already supply it.
