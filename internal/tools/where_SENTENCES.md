# Where answers (`where.go`)

- WG-BOUND — A read still unanswered when the bound passes leaves its fact not read and the answer still comes with every fact that was read.
- WG-WIRE — The early envelope snapshot exposes stages before lease reconciliation without changing the envelope tools return.
- WG-STANDING — Where lists only open changes without a working copy, while their standing leaves existing tool JSON unchanged.
- WG-FRESH — A copy's edit step uses HQ's answer to this call; a last-heard change or absence remains unknown.
- WG-HEAD — A detached checkout and an unborn branch say which branch or commit is absent instead of saying the checkout did not answer.
- WG-GROUP — An unread lease does not hide work in another copy, but no copy is handed over until its branch group is read.
- WG-DESCRIBEDHEAD — A description is handed over only if the branch-group plan still says the same change and commit are handed over.
- WG-KEPTHEAD — Kept description words cannot be reused at another commit without rewriting them.
- WG-KEPTSTEP — When kept words belong to another commit, the reply names the current branch step until HQ holds the addressed commit; only then does it ask for words for that commit.
- WG-MOVEDSTEP — When HQ refuses a description because its head moved, the kept words stay at their commit and the reply names the branch's next step.
- WG-ACKHEAD — An acknowledgement for one commit cannot discard identical words kept for another commit.
- WG-DESCRIBECOPY — Describing cannot choose arbitrarily between several addressed checkouts.
- WG-REVIEWPROMISE — A handover promises an awaiting Review build only when HQ reports it for that commit.
