- KL-1 — Without a check or setup the tool asks HQ for the change's failing checks; with a setup it reads that Review build, and with a check it reads that check's log and HQ's current head, sending only the range and pattern the agent gave, under the Mate's key. Breaks: the agent reads another change's or no check's log.
- KL-2 — What the agent reads is HQ's answer as lines: each failing check by name, conclusion, id and page, or the log's counts and each line under its number, a cut line and a log read in part said so. Breaks: an agent takes a cut answer for the whole log.
- KL-3 — Each refusal of HQ is said in words that tell the agent what it is and whether asking again helps; a missing Actions grant is said as a person's to give. Breaks: an agent retries a refused read or hunts for another way to the log.
- KL-4 — The checks list names failed Review build parts beside failed GitHub checks and says when the Review build belongs to an older head. Breaks: an agent repairs only one source or the wrong commit.
- KL-5 — A setup selects its Review build's platform lines or health observation, and a failed read is not said to mean no log. Breaks: an agent cannot diagnose the named part or mistakes an outage for missing logs.
- KL-6 — HQ's refusal says whether the change was merged, closed, or is simply not open. Breaks: a queued notice sends the agent to repair a finished change.
- KL-7 — A GitHub log names the run's head and says when the change now has another head. Breaks: the agent attributes an older failure to the current commit.
- KL-8 — A Review build log omits a complete startup banner but keeps a truncated or unfamiliar log. Breaks: the agent reads the builder's art instead of the failure, or loses log output.
