# Where the work stands (`where.go`)

- WH-COPY — The where text names each working copy with its part, branch, what is uncommitted and unpushed, its change and each dev server's state, the caller's own first and marked, and is empty when there is nothing to name. Breaks: an agent back from a compaction works in another conversation's copy, or asks status to learn its branch.
- WH-COUNTS — A working copy names one uncommitted file or unpushed commit in the singular and larger counts in the plural.
- WH-DETACHED — A detached working copy's branch is named as detached, while a named branch keeps its name.
- WH-UNREAD — A fact that was not read says not read with why, never clean, none or nothing. Breaks: a copy whose container did not answer reads clean and its unsaved work is released.
- WH-STAGE — A stage's line says the name of the version it runs exactly as the platform holds it, and says when it runs none. Breaks: the agent rebuilds a stage that already runs its commit, or tests one that runs another branch.
- WH-SIZE — The text never passes 1024 bytes: line 1 and the caller's copy stay, later whole lines give way to one line counting them. Breaks: every message of a Mate with many leases carries kilobytes, or the cut drops the caller's own copy.
- WH-ACQUIRE — With no pool copy on a branch, the next edit step is to acquire one.
- WH-CHECKOUT — With no copy of a change's branch on a classic pair, a clean dev half can check it out when handed over, on main with nothing unpushed, or on a branch whose head origin's main holds.
- WH-OCCUPIED — A classic dev half is occupied when dirty, when main has unpushed commits, or when another branch with work main lacks is not handed over; an unread checkout, unpushed work or handover cannot authorize a checkout.
- WH-COPYREAD — An unread copy or branch ref makes its next edit step unknown and names the missing read.
- WH-FRESH — A last-heard or failed HQ read cannot establish a change or its absence for an edit.
- WH-COMMIT — Uncommitted work is committed before pulling, pushing or describing the change.
- WH-PULL — A copy behind its branch's remote ref pulls before handover.
- WH-DIVERGED — A copy diverged from its branch pulls and then pushes; unknown remote history first needs a pull.
- WH-PUSH — A branch missing on origin or with commits ahead of its own ref is pushed even if another branch has those commits.
- WH-OPEN — A published, clean branch with no open change opens one with a description.
- WH-HEAD — A change at another or unread head cannot establish handover of this copy.
- WH-DESCRIBE — A draft at the published head is described before handover.
- WH-HANDED — A ready change at the clean, published head is handed over when its Review build has not failed at that head.
- WH-REPAIR — A failed add at the published head directs the copy to read each failed setup’s log, fix and verify in the same draft, then commit and push for an automatic rebuild.
- WH-STEPWORDS — A step names the copy or missing read, and a handed-over change names its first seven commit characters.
- WH-EDITLINE — A copy's where line carries its edit step and the Review build label for its change.
- WH-GROUP — A branch is not handed over while another copy is unread or holds work, but a readable copy's work remains actionable.
- WH-BASE — When main moved, the next edit of an open draft first brings it into that draft; handover alone does not require this update. Breaks: a draft misses already added work or delays its first handover.
- WH-GIVENUP — An add whose failed tries are exhausted asks the person instead of starting another repair. Breaks: the agent retries after HQ handed the failure to the person.
