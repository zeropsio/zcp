# Pool template, repository half (`pool_template.go`)

- PT-SEED-POOL — A seed gives each part a pool setup named after its pool that builds and runs on the part's own runtime type, never the pool's `swarm@1`, installs zcp-devsup and starts `zcp-devsup run`, so a lease's container has the part's toolchain under the supervisor.
- PT-SEED-PORTS — A seed's pool setup declares exactly the ports previewPortBase + 1 … previewPortBase + maxContainers, each with httpSupport, so every lease's preview has its port and no port beside them is opened.
- PT-SEED-STAGE — A seed gives each part a stage setup named after the part that deploys `./`, with the idle start for a runtime that takes a start command and none for a static one, so the stage builds before the part has code.
- PT-CHECK-MISSING — A main holding code without the parts' setups is refused naming each part's missing pool setup, each missing stage setup and the missing dev-server declaration, so the person knows what to add.
- PT-CHECK-SEED — The seed's own two files pass the setup check, so a plan sent again on a seeded main writes nothing and is never refused.
- PT-SEED-UNBORN — A repository with no main is never seeded and a main holding a file is never written: only HQ's own empty first commit takes the seed, because HQ lands a Mate's first change nowhere else. Breaks: a person's empty repository gets an open seed change HQ refuses on every run, and the plan is refused for good.
- PT-SEED-FOREIGN — The seed is written only onto a change opened for it: another open change HQ hands back, or a seed change whose head holds other files, is refused and written nothing. Breaks: a Mate's open change of code is replaced by the two seed files and its code is lost from the change.
- PT-SEED-RESENT — A plan sent again after a stop reuses its open seed change: a head that is the seed already is written nothing, and a head holding the seed's files with other content gets one commit of the seed on it. Breaks: a second commit of the same seed, or a parentless commit refused as non-fast-forward, stops every later run.
- PT-SEED-ORPHAN — A seed change HQ did not land is closed once main was written by another, and left as it is when main holds the seed's own landing. Breaks: an orphan change stays open counting against the Mate's open changes, or a landed seed's lost answer closes nothing that exists and fails the plan.
- PT-SEED-LEFT-OPEN — A plan sent again onto a main another wrote closes the seed change an earlier run left open, and closes no other change. Breaks: the orphan seed change stays open for good, counting against the Mate's open changes and handed back as its default change with a root unrelated to main, or the Mate's open change of code is closed.
- PT-SEED-LANDED-BENEATH — Closing a seed change HQ answers no longer open (landed beneath a change on top of it, or closed meanwhile) settles the seed; any other answer fails the plan. Breaks: a seed that landed with its answer lost fails the plan with "could not be closed", or a refused close passes as done.
