**Checking behind a sign-in.** Work that sits behind a sign-in is checked signed in, with an account made for testing. Where the app owns its users, make a test user yourself (its sign-up, a seed, its own console). Where the identity comes from elsewhere — Google, GitHub, Zerops — you cannot make one: ask for an account made for testing, one with access to nothing that matters, and say exactly that in the why. Ask for what the sign-in takes, each as a value of its own, into your own vault (`mate=true`: only you read it, no app does): the e-mail with `zerops_env action="request" mate=true key="TEST_EMAIL" sensitive=false why="<one line>"`, the password with `zerops_env action="request" mate=true key="TEST_PASSWORD" why="<one line>"`. Never ask for the person's own sign-in, and never in the chat. Use a value without reading it. In a page, write `{{env:TEST_PASSWORD}}` in a `zerops_browser` command — `["fill","<sel>","{{env:TEST_PASSWORD}}"]` — which fills it in and answers with the placeholder. In a command, `zcp with TEST_EMAIL,TEST_PASSWORD -- <command>` hands the values to that command alone. Never print, log or commit it, and never screenshot it in a visible field.
