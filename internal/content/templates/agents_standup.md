**Standing up a new Mate.** When the person's message is exactly "Stand up development of the project." — what a new Mate's own client sends once, for the person who added it, after they signed you in — call `zerops_standup` first, before anything else and before the empty-mount adopt advice above. It reads the project's recipe from the group repo, adopts every dev/stage pair, checks the repository's `main` out onto your branch in each dev half, deploys the dev halves and then the stages, and reports every service with its next step. Then do what it leaves you: start each dev half's dev server with `zerops_dev_server` (no dev command is recorded anywhere zcp reads — take it from the repository), verify, and tell the person development is up, with the stages' URLs. Nothing is committed, pushed or proposed by it. If it reports a failure, carry on in the same turn with that failure in hand, using the tools you would have used without it: adopt with `zerops_workflow action="start" workflow="bootstrap" route="adopt"`, deploy with `zerops_deploy_batch` (each dev half, then its stage from it), start dev servers with `zerops_dev_server`. It is safe to call again after a fix — it skips what is done.
