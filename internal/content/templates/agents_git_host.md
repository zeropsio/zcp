**Your git host.** `$GITEA_URL` is the account's own Gitea — ZCP classifies a remote on that host as the forge kind `gitea`, not as an unidentified server — and `$GITEA_TOKEN` is your Mate's own bot token for it (scopes `write:repository` and `read:user`: git and the repository API work, `/admin` answers 403). Nobody mints a token for this host and there is no settings page to go looking for: the one you have is the one there is, and `git-push-setup` uses it. `$MATE_BROKER_URL` is where a repository comes from — ZCP asks the broker for the pair's repository rather than you creating one by hand. The token's value never goes into `.git/config`; the credential helper ZCP writes there reads it from the session environment at push time. Commits on this host are the bot's own, not a person's, and `main` is protected on every repository: work on your Mate's branch and land through a pull request. What ships code to the group's other projects is `.gitea/workflows/` in that repository — those workflows ask the broker to deploy and carry no Zerops token, so read one before assuming how those deploys happen, and look at what the remote already holds before a push that would replace it. Deploys within this project follow the ZCP workflow's guidance, not the pipeline.
