## 5. Decisions taken (do not re-litigate without new evidence)

1. **The published artifact carries the identity; the workspace package does not.** `zerops-code` /
   `z3` ship; the workspace stays `t3` for ported-zone diffability. The divergence lives in one place,
   `apps/server/scripts/cli.ts`, with the reason beside it.
2. **The digest compiled into `zcp` is the integrity authority**, never the release's `SHA256SUMS`.
3. **A Zerops server refuses the credential it never issues** (no session cookie), and CORS there is
   un-credentialed. That is what makes the origin allowance safe.
4. **The origin allowance trusts every Zerops tenant, not the vendor** — `https://*.zerops.app|.dev|.io`
   over https, dot-anchored. Safe only in combination with 3.
5. **Deletion over redirection** for the registry paths (§3): a half-built update path is worse than
   none.
6. **Timing is not a test.** Two guards were rewritten today after measuring the machine; the rule now
   is to count work.
7. **Merge as a unit** where safety composes: the origin widening never lands without the cookie
   refusal in the same merge.

## 7. How to run and verify

**The app**: https://zcp-26a7-8080.prg1.zerops.app/z3/ — sign in with a Zerops account. Expect a
populated sidebar, numbers at `/z3/usage`, the Zerops mark, and — after a 15-minute idle — an automatic
recovery with no click.

**The release**:
```bash
curl -sL -O https://github.com/zeropsio/z3/releases/download/v0.1.0/zerops-code-0.1.0.tgz
shasum -a 256 zerops-code-0.1.0.tgz     # e40c9407bcf373265508bbf887dd284389f7ee94de89dcd8b62c7429174d57ca
npm init -y && npm install ./zerops-code-0.1.0.tgz && ./node_modules/.bin/z3 --version
```

**The container** (VPN first: `zcli vpn up nTV3oMB2SS634ImDJnQckg`, needs sudo):
```bash
ssh zcp
ps aux | grep '[z]3 serve'
cd /home/zerops/.zcp/z3 && npm ls --depth=0        # zerops-code@0.1.0
journalctl -u zerops@z3 -f
sudo grep -E 'zerops-identity|oauth/token|websocket-ticket' /var/log/nginx/access.log.1 | tail
```
The access log is the record of a sign-in: `zerops-identity 200` → `oauth/token 200` →
`websocket-ticket 200`. A **401** on the ticket means the session expired — after W5b the client should
re-mint by itself. Note nginx writes to `access.log.1`, not `access.log`.

**The suites**:
```bash
cd ../z3   && vp test run apps/web/src --exclude "**/runtimeAbi.test.ts"   # 2920
            vp test run apps/server/src                                     # 2875
            vp test run apps/desktop/src                                    # 420
cd ../zcp  && go test ./... -short && make lint-fast
```
A fresh z3 worktree needs `CI=true vp i --frozen-lockfile --offline`; a fresh **zcp** worktree needs the
gitignored knowledge corpus copied in (`internal/knowledge/{recipes,guides,decisions}/*.md`) or two
packages fail for a reason that is not yours.

**Releasing again**: bump `apps/server/package.json`, commit, tag `vX.Y.Z`, push the tag. The workflow
refuses a tag that disagrees with that file. Then update `PinnedVersion` **and** `PinnedSHA256` in
`internal/z3/z3.go` in the same commit.
