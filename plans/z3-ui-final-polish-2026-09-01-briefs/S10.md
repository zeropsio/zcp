# Slice brief: S10 — Always-available workspace thread action

**Outcome**: Every workspace has one compact `New thread in …` action. It reuses the exact existing
untouched shell, otherwise creates a draft against that member's scoped project ref.

**Allowed scope**: `apps/web/src/components/Sidebar.logic.ts`, `apps/web/src/components/Sidebar.tsx`,
`apps/web/src/components/sidebar/SidebarProjectTree.tsx` and their focused tests. No project-grouping,
contract, persistence or command-palette changes.

**Spec citation**: `docs/spec-z3.md` §5.4.

**RED tests**: workspace action exists with and without a compact shell; the first untouched shell is
hidden/reused, extras remain; collapsed action and sibling-button semantics persist; action resolver
chooses `open-existing` before `create-in-workspace`.

**Protocol**: RED → GREEN → REFACTOR, focused `vp test run`, web typecheck and lint. Stop on scope or
acceptance drift.
