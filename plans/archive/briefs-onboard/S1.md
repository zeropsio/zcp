# Slice brief: S1 — Tracer: playbooks knowledge family + stub doc + fetch/search-exclusion tests

Self-contained. Cite docs/spec-onboarding.md §5 (promoted at GATE 1 — the normative
contract is restated verbatim below; treat the literals here as the spec oracle).

**Outcome** (observable): `zerops_knowledge uri="zerops://playbooks/onboarding"` returns an
embedded stub document in an UNSYNCED checkout, and no `zerops://playbooks/*` document ever
appears in `query=` search hits.

**Allowed scope**
- Files (write-set): `internal/knowledge/documents.go` · `internal/knowledge/engine.go` ·
  `internal/knowledge/playbooks/onboarding.md` (new stub) ·
  `internal/knowledge/engine_playbooks_test.go` (new) ·
  `internal/tools/knowledge_playbooks_test.go` (new)
- Explicitly excluded: any other file; especially `internal/tools/knowledge.go` (the uri=
  fetch path needs ZERO change — non-atom URIs already fall through to `store.Get`),
  `internal/knowledge/corpus_guard.go`, any sync code, any content template.

**Contract (spec §5)**
- `playbooks/` is a committed, repo-owned knowledge family: add `all:playbooks` to the
  `//go:embed` directive (documents.go:10) and `"playbooks"` to `knowledgeDirs`
  (documents.go:14). URI derivation is mechanical (`pathToURI`): `playbooks/onboarding.md`
  → `zerops://playbooks/onboarding`. go:embed fails the build if the pattern matches zero
  files — the stub doc lands in the same commit.
- The family is **direct-fetch-only**: `Store.Search` (engine.go — the single all-docs
  scoring loop, currently `for uri, doc := range s.docs` at ~:118) must `continue` on URIs
  with prefix `zerops://playbooks/`. `Store.Get` stays family-blind (fetch keeps working).
- Stub doc content (replaced by S3 — keep it minimal but real):
  ```markdown
  ---
  description: Conversation playbook for onboarding a new user to Zerops.
  ---

  # Onboard me to Zerops — conversation playbook

  Placeholder — the conversation contract lands in a follow-up slice.
  ```

**RED test list**
- `TestSearch_ExcludesPlaybooks_NoHits` — layer: unit (`internal/knowledge`,
  engine_playbooks_test.go). Hand-BUILD a store — NOTE the real signatures:
  `store, err := NewStore(...)` returns `(*Store, error)` (check err), and Search is
  `store.Search("deploy app", 10)` — `(query string, limit int)`. Store contains one
  playbook doc whose title/body are rich in otherwise-matching terms (e.g. "deploy app
  service") plus one ordinary guide doc; assert zero hits with the playbooks prefix and
  ≥1 hit for the guide. Pre-implementation this FAILS (playbook doc scores and is
  returned) — a real assertion RED. See store_access_test.go for hand-built-store
  patterns.
- `TestKnowledgeTool_PlaybookURI_FetchesEmbedded` — layer: tool (`internal/tools`,
  knowledge_playbooks_test.go). Use `knowledge.GetEmbeddedStore()` (NO corpus-sync skip —
  a committed playbook is embedded even unsynced; do NOT copy the `SyncedCorpusPresent`
  skip pattern) and drive the knowledge tool handler exactly like
  `TestKnowledgeTool_FetchMode_ReturnsFullDocumentBody` (knowledge_test.go:261-278) with
  `uri="zerops://playbooks/onboarding"`; assert the response body contains
  `# Onboard me to Zerops`. Pre-implementation this FAILS with the not-found error path —
  assertion-level RED.

**Environment note**: `internal/knowledge` package tests are gated by a package-level
TestMain corpus guard (corpus_guard_main_test.go) that exits when the synced corpus is
absent — a hand-built store does NOT bypass it (it runs before every test in the package).
The ORCHESTRATOR pre-copies the synced corpus (gitignored `recipes/guides/decisions` .md
files, verified ≥ the 5-recipe floor at the source) into EVERY worktree involved: this
executor worktree, the RED-replay scratch worktree, and the integration tree. If
`go test ./internal/knowledge/...` aborts with the "knowledge corpus not synced" message,
STOP and report blocked — do not weaken or bypass the guard, do not sync yourself.

**Protocol**: RED → GREEN → REFACTOR.
1. Write the named test(s) first; confirm each fails for the right reason:
   `go test ./internal/knowledge -run TestSearch_ExcludesPlaybooks_NoHits -short -count=1 -v`
   `go test ./internal/tools -run TestKnowledgeTool_PlaybookURI_FetchesEmbedded -short -count=1 -v`
2. Implement until green: same commands, must pass.
3. Refactor with tests green; re-run; then `make lint-fast`.

**BUILD addendum (flow)**
- Never batch-write tests: RED → GREEN → REFACTOR one named test at a time.
- Independent oracle: expected values come from the contract literals above, never
  recomputed the implementation's own way.
- Assert on public seams only (Store.Search/Store.Get/tool handler output) — never an
  internal helper.
- Table-driven, `Test{Op}_{Scenario}_{Result}` naming; one layer-matrix pass line per
  touched layer (unit: ./internal/knowledge, tool: ./internal/tools).
- `make lint-fast` clean before the slice reports done.
- Do NOT run any `git commit`/`branch`/`stash`/`push` — leave every change uncommitted in
  the working tree; integration is the orchestrator's job.
