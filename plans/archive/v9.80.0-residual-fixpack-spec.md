## Fix 2 — `requirePriorityJustificationBlock` gate

**Problem.** Every tier `import.yaml` declares `priority: 10` on managed services (db, cache, broker, search) but no tier carries a TY5-class explanation block. Jetstream golden has it on every tier:

```yaml
services:
  - hostname: app
    # ... runtime block
  
  # Set higher priority for databases and storages,
  # because the app depends on those services.

  # Deploy single node PostgreSQL database, ...
  - hostname: db
    priority: 10
```

Run-36/37/38 = 0/6 tiers. Substrate teaches the canonical form (TY5 in `develop-first-deploy-scaffold-yaml.md` etc.); agent has not authored it three runs running.

**Where:** new file `gate_priority_justification.go`, registered in `EnvGates()`.

**Spec:**

```go
// gate_priority_justification.go — v9.80.0 Fix 2.
//
// Refuses env-content complete-phase when any tier import.yaml that
// declares `priority: 10` on a managed service has no TY5-class
// explanation comment block ahead of the first such service. The
// block must explain WHY databases/storages get higher priority
// (boot-order dependency: runtimes need managed deps reachable).
// Substrate teaches the form verbatim; gate enforces presence.
//
// Recognition heuristic: a `# ` comment block (≥1 contiguous lines)
// appearing between the last runtime service block and the first
// `priority: 10`-bearing managed service, containing both a
// "priority"-class noun and a "depends"-class verb (or equivalent
// causal connector). Strict-form detection is intentional — we
// want to refuse silent-skip but not police phrasing variations.

func gateRequirePriorityJustification(ctx GateContext) []Violation {
    var out []Violation
    for _, tier := range Tiers() {
        path := filepath.Join(ctx.OutputRoot, tier.Folder, "import.yaml")
        raw, err := os.ReadFile(path)
        if err != nil {
            continue
        }
        if !hasPriorityServices(string(raw)) {
            continue // tier doesn't use priority — skip
        }
        if !hasPriorityJustificationBlock(string(raw)) {
            out = append(out, Violation{
                Code:     "missing-priority-justification-block",
                Path:     path,
                Severity: SeverityBlocking,
                Message: fmt.Sprintf(
                    "tier %d (%s) declares `priority: 10` on managed services but has no TY5-class justification comment ahead of them. Add a comment block explaining WHY (canonical form: \"# Set higher priority for databases and storages,\\n# because the app depends on those services.\"). Author in `env/%d/import-comments` and re-close phase=env-content.",
                    tier.Index, tier.Folder, tier.Index,
                ),
            })
        }
    }
    return out
}

// block declaring `priority: 10` (or higher).

// hasPriorityJustificationBlock reports whether the yaml carries a
// contiguous `# ...` comment block that mentions both a priority
// noun ("priority", "boot-order") AND a dependency verb ("depend",
// "requires", "needs") between the first runtime service and the
// first `priority:`-bearing service.
func hasPriorityJustificationBlock(yaml string) bool { /* ... */ }
```

## Fix 3 — pre-flight engine version stamp in `plan.json`

**Problem.** Run-36 cost a full prod dogfood because the dev container's `zcp` binary was never rebuilt after the last engine fix landed. Run-38 prevented a repeat only because validation manually ran 6 smoke checks. The user pays per dogfood; this class of failure must be impossible by construction.

**Codex correction (2026-05-10):** original draft had `internal/recipe/gate_engine_version_stamped.go` import `internal/server` to read `server.Version`. That creates an import cycle — `internal/server` already imports `internal/recipe`. Original draft also mis-located the stamp site as `handlers.go::handleStart`; `Plan{}` is actually constructed inside [`NewSession` at `workflow.go::83-90`](../internal/recipe/workflow.go#L83-L90) and persistence happens later (`mergePlan` / first `update-plan` at `handlers.go::862-918`). Both issues are addressed below.

### Architecture decision: thread version through `GateContext`, not via cross-package import

Add an `EngineVersion string` field to [`GateContext` at `gates.go::21`](../internal/recipe/gates.go#L21). Caller (the workflow loop that already builds `GateContext` at [`workflow.go::134`](../internal/recipe/workflow.go#L134) + [`workflow.go::175`](../internal/recipe/workflow.go#L175)) passes the live binary version it received from the entry-point handler. The gate is a pure function on the context — no `internal/server` import needed, no cycle.

Where the version originates:
- [`cmd/zcp/main.go`](../cmd/zcp/main.go) → calls into the MCP/CLI handler in `internal/server` → `internal/server.Version` (ldflags-injected) is passed down to `internal/recipe` handlers as a parameter; the handler threads it into `GateContext.EngineVersion` at every workflow checkpoint.
- The handler signature for the MCP entry into `internal/recipe` likely already takes config/options. Add a new option (e.g. `WithEngineVersion(string)` or extend the existing options struct) — find the existing pattern at [`handlers.go::handleStart`](../internal/recipe/handlers.go) (whichever entry constructs `NewSession`).
- Default value when the option is unset = `"dev"` (matches `server.Version`'s zero-value at [`internal/server/server.go::28`](../internal/server/server.go#L28)).

### Stamp site

Modify [`NewSession` at `workflow.go::83-90`](../internal/recipe/workflow.go#L83-L90) to take an `engineVersion` parameter and write it into the freshly-constructed `Plan{}`:

```go
// internal/recipe/workflow.go — v9.80.0 Fix 3.
func NewSession(slug, engineVersion string, factsLog *FactsLog, outputRoot string, parent *ParentRecipe) *Session {
    return &Session{
        Slug:       slug,
        Current:    PhaseResearch,
        Plan:       &Plan{Slug: slug, EngineVersion: engineVersion}, // stamped at construction
        FactsLog:   factsLog,
        Parent:     parent,
        OutputRoot: outputRoot,
        Completed:  map[Phase]bool{},
    }
}
```

Add `EngineVersion string \`json:"engineVersion,omitempty"\`` to [`Plan` struct at `plan.go::16`](../internal/recipe/plan.go#L16). The first `WritePlan` call (which triggers via `mergePlan` on the first `update-plan` action — codex confirmed) writes the value to disk; the gate reads it back from `ctx.Plan.EngineVersion` on every phase close.

Every `NewSession` call site updates: at minimum the `action=start` handler in `handlers.go`. Search-and-replace breaks the build cleanly so no call site is missed; that's the safety mechanism, not a maintenance burden.

### Gate

```go
// internal/recipe/gate_engine_version_stamped.go — v9.80.0 Fix 3.
//
// Refuses any complete-phase when plan.EngineVersion is empty OR
// disagrees with the binary's current EngineVersion (passed via
// GateContext.EngineVersion, populated by the workflow caller from
// internal/server.Version). Hard preflight against run-36-class
// binary-version drift: agent runs against a stale `zcp` binary,
// ships a recipe under engine semantics that don't match prod.
//
// Graceful skip when ctx.EngineVersion == "dev" — developer-machine
// runs (no ldflags injection) are out of scope. Production builds
// set Version to the git tag, so this gate fires only on
// production-binary mismatch.

func gateEngineVersionStamped(ctx GateContext) []Violation {
    if ctx.EngineVersion == "dev" {
        return nil // dev binary, no stable version to compare against
    }
    if ctx.Plan == nil || ctx.Plan.EngineVersion == "" {
        return []Violation{{
            Code:     "engine-version-not-stamped",
            Path:     "plan.json",
            Severity: SeverityBlocking,
            Message:  "plan.EngineVersion is empty. Recreate the session via action=start with the current zcp binary so the engine version is recorded for downstream validation.",
        }}
    }
    if ctx.Plan.EngineVersion != ctx.EngineVersion {
        return []Violation{{
            Code:     "engine-version-mismatch",
            Path:     "plan.json",
            Severity: SeverityBlocking,
            Message: fmt.Sprintf(
                "plan was authored under engine version %q; current zcp binary is %q. Rebuild the dev-container zcp binary (or recreate the session under the current binary) before continuing — silent version drift cost run-36 a full dogfood.",
                ctx.Plan.EngineVersion, ctx.EngineVersion,
            ),
        }}
    }
    return nil
}
```

Register in `DefaultGates()` (fires at every phase close; cheap two-string-comparison; matches the existing fact-quality default-gate pattern).

**Behavior pin (`gate_engine_version_stamped_test.go`):**

| Case | Verdict |
|---|---|
| Plan with empty `EngineVersion` | block |
| Plan with `EngineVersion = server.Version` | pass |
| Plan with `EngineVersion = "v9.78.0"` while `server.Version = "v9.80.0"` | block |
| Plan with `EngineVersion = "dev"` while `server.Version = "dev"` (developer machine) | pass |
| Plan with `EngineVersion = "v9.78.0"` while `server.Version = "dev"` (developer machine inspecting prod plan) | pass (graceful skip — dev binary can't compare) |

**CLAUDE.md update:** add an invariant under the Conventions list — *"Engine version stamps the plan — every fresh session writes `plan.EngineVersion = server.Version` before the first `WritePlan()`; any complete-phase refuses when missing or mismatched against the running binary. Pinned by `TestGateEngineVersionStamped_*`."*

```go
// gate_object_storage_priority.go — v9.80.0 Fix 6.
//
// Refuses env-content close when any `type: object-storage` service in
// a tier has Priority == 0 while sibling managed services (db/cache/
// broker/search) in the same tier carry Priority > 0. Object-storage
// is a boot-order peer of managed databases; the agent shouldn't
// silently downgrade it. Reads `Plan.Services` directly — emitter
// already maps `Priority > 0` 1:1 with the rendered `priority:` line.
//
// Per-tier services live in `Plan.Services` keyed by tier index via
// the existing service-set composition pipeline; if Plan.Services
// itself is whole-recipe (not per-tier), iterate via the tier-yaml-
// aware path that Fix 2 uses (parse `Plan.Services` filtered by
// the same service-set the tier emits). Verify the actual data shape
// at implementation time — the gate logic stays the same either way.

func gateRequireObjectStoragePriority(ctx GateContext) []Violation {
    if ctx.Plan == nil {
        return nil
    }
    siblingsHavePriority := false
    for _, svc := range ctx.Plan.Services {
        if svc.Kind == ServiceKindManaged && svc.Priority > 0 {
            siblingsHavePriority = true
            break
        }
    }
    if !siblingsHavePriority {
        return nil // recipe doesn't use priority at all — skip
    }
    var out []Violation
    for _, svc := range ctx.Plan.Services {
        if svc.Type != "object-storage" {
            continue
        }
        if svc.Priority == 0 {
            out = append(out, Violation{
                Code:     "object-storage-missing-priority",
                Path:     fmt.Sprintf("services[%s]", svc.Hostname),
                Severity: SeverityBlocking,
                Message: fmt.Sprintf(
                    "object-storage service %q has no priority while sibling managed services declare priority > 0. Object-storage is a boot-order peer of managed databases — the runtime depends on it. Set `Priority: 10` on the service entry (mirrors db/cache/broker/search); rerun `complete-phase phase=env-content`.",
                    svc.Hostname,
                ),
            })
        }
    }
    return out
}
```

```go
//
// Refuses codebase-content complete-phase when any codebase's
// `codebase/<h>/knowledge-base` fragment body doesn't start (after
// leading whitespace) with an H3 heading line `### <Topic>`. KB1 in
// derived_rules.md teaches that the Zerops dashboard's KB extractor
// expects H3-rooted content; H2 or flat-bullets-only forms are
// silently dropped on the recipe page render.
//
// Run-36/37/38 evidence: substrate-only teaching has not landed —
// apidev shipped flat-bullets-only three runs running; appdev +
// workerdev shipped H2 forms two runs running. Empirical render
// verification (laravel-minimal vs nestjs-showcase apps-repo
// READMEs at github.com/zerops-recipe-apps/, 2026-05-10):
// laravel-minimal `### Gotchas` H3 renders on dashboard; nestjs-
// showcase-app `## Tips and Others` H2 doesn't.

func gateRequireH3InKnowledgeBaseFragment(ctx GateContext) []Violation {
    if ctx.Plan == nil {
        return nil
    }
    var out []Violation
    for _, cb := range ctx.Plan.Codebases {
        if cb.Hostname == "" || cb.SourceRoot == "" {
            continue
        }
        fragId := fmt.Sprintf("codebase/%s/knowledge-base", cb.Hostname)
        body, ok := ctx.Plan.Fragments[fragId]
        if !ok {
            continue // fragment not yet recorded — absence-of-KB caught by other gates
        }
        if !startsWithH3Heading(body) {
            out = append(out, Violation{
                Code:     "kb-fragment-not-h3-rooted",
                Path:     filepath.Join(cb.SourceRoot, "README.md"),
                Severity: SeverityBlocking,
                Message: fmt.Sprintf(
                    "codebase/%s knowledge-base fragment body must start with an H3 heading (`### <Topic>`) per derived_rules.md §KB1. The Zerops dashboard's KB extractor expects H3-rooted content; H2 (`## ...`) and flat-bullet-only forms are silently dropped on the recipe page render. Re-author via `record-fragment fragmentId=%s mode=replace` with a body that opens `### Gotchas` (or `### <Topic>`) followed by paragraphs / bullets.",
                    cb.Hostname, fragId,
                ),
            })
        }
    }
    return out
}

// startsWithH3Heading reports whether body's first non-blank line
// is a markdown H3 (`### `). Leniency on leading blank lines so
// `\n\n### Gotchas` passes.
func startsWithH3Heading(body string) bool {
    for _, line := range strings.Split(body, "\n") {
        trimmed := strings.TrimSpace(line)
        if trimmed == "" {
            continue
        }
        return strings.HasPrefix(trimmed, "### ")
    }
    return false
}
```
