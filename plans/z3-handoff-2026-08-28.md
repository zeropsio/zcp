## 5. Rules that were paid for today (keep them)

- Only the orchestrator runs `eval/scripts/z3-dev-push.sh`; a container RESTART (not a unit restart) wipes the dev build.
  Deliver the fork with `Z3_BASE_PATH=/z3 ./eval/scripts/z3-dev-push.sh z3`; read the script's exit code and `npm ls t3` on the container, never a grep of its output.
- A raw WebSocket probe of a `subscribe*` RPC must send `[{"_tag":"Ack","requestId":"<id>"}]` after every Chunk (effect-rpc flow control) — an unacked probe gets one Chunk and looks like a dead feed. Real clients ack automatically.
- The Zerops L7 closes an idle WebSocket at 60 s; the product client pings every 5 s. Probes must keep traffic flowing.
- `zerops@z3`'s process env = the container's live env store (`/etc/zerops-zembed/env.json`) + `~/.zcp/z3.env`; a service env change needs `sudo systemctl restart zerops@z3`.
- The identity session is a 15-minute membership window that re-mints silently; a one-time pairing keeps upstream's TTL. Do not "fix" either direction.
- The auto-bootstrap creates `www` only when no active project owns `/var/www`; agents' test projects mask it — delete them before judging the bootstrap.
- Load averages inside these containers are the physical node's; judge idleness by `ps`.
- Ledger discipline: subagents report facts as text; one writer edits `docs/internals/zerops/*`.

## 6. How the work was run (repeat it)

Streams ran as parallel subagents, one per stream, each in its own git worktree (`../z3-wt/<stream>` for the fork,
`.claude/worktrees/...` for zcp), plan first (a `plans/z3-<stream>-plan-*.md` with a seam map), RED → GREEN per slice,
reports via SendMessage only (plain-text turns are lost), the orchestrator merging into the integration branch (`z3` /
`feat/z3`) at slice boundaries after re-running the union's tests, pushing to the container, and having a separate verifier
agent run the live checks with the owner's tokens read into shell variables and never printed. Coordination facts (env
names, the Zerops-environment rule `T3CODE_ZEROPS_PROJECT_ID`, contract shapes) were broadcast to every affected stream the
moment they were decided. Sandbox-pinned subagents cannot create a second worktree — they check out a branch inside their own.
