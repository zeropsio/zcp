# R4 — z3 desktop anatomy

## Summary
1. The desktop app is the web bundle inside one Electron BrowserWindow loaded from `t3code://app/`; that custom scheme is a proxy to the LOCAL backend's HTTP server, which serves `apps/web/dist` (`ElectronProtocol.ts:217`, `DesktopApp.ts:178-186`, `server/config.ts:229-247`). The main window is only created when the local backend reports ready (`DesktopBackendPool.ts:295` → `DesktopWindow.ts:782-788`). A remote-only build therefore needs a new renderer source (packaged static dir or hosted origin) and an unconditional window open — this is the real S5 cost, not feature hiding.

2. Brand is hard-coded in three places that do not share a constant: `DesktopEnvironment.ts:88` (`APP_BASE_NAME="T3 Code"`, dir names, AUMID, wmClass), `build-desktop-artifact.ts:55,2144-2242` (appId `com.t3tools.t3code`, productName from `apps/desktop/package.json:38`, artifactName, protocols, DMG), and web (`SidebarChrome.tsx:93-120` inline T3 wordmark SVG, `index.html:456`, `branding.ts:19`). `DesktopAppBranding.stageLabel` is a closed literal union `Alpha|Dev|Nightly` (`contracts/ipc.ts:158`), so a Zerops build cannot pass a new stage without a contracts change; baseName/displayName can be set from main alone.

3. Tailscale is already removed end-to-end (`verified.md:447`); local spawn, WSL and SSH launch remain fully wired and ungated except by `window.desktopBridge` presence and settings defaults. The scheme rename is out of scope per brief §5 (line 225-226); `t3code://app` is already in the Zerops origin allowlist (`server/zerops/origin.ts:31`).

4. Titlebar: macOS `hiddenInset` + traffic lights at (16,18) with a 90px web inset; Win/Linux WCO overlay height 40 vs web topbar 52; every inset flows through `--workspace-*` CSS vars (`index.css:106-134`).

5. No release/signing workflow exists in the fork (`.github/workflows/ci.yml` only); signing needs Apple Team ID + optional Clerk passkey profile, Windows needs Azure Trusted Signing; packaging needs cargo for the Rust resource monitor.

## 1. What the desktop app IS visually

**Confirmed: the web bundle in one `BrowserWindow`.** `apps/desktop/src/window/DesktopWindow.ts:322,623` loads `getDesktopUrl(isDevelopment)` = `t3code://app/` (`apps/desktop/src/electron/ElectronProtocol.ts:11-25`). The scheme is registered privileged (`:111-131`) and handled by `proxyRequest` (`:140-183`), which rewrites every `t3code://app/<path>` to `targetOrigin` — in production the **local backend's** `httpBaseUrl`, in dev the Vite server (`apps/desktop/src/app/DesktopApp.ts:178-186`). The local backend serves the web bundle from `apps/server/dist/client` or `apps/web/dist` (`apps/server/src/config.ts:229-247`, `apps/server/src/http.ts:391-435`). The proxy injects a CSP (`ElectronProtocol.ts:67-96`: Clerk origin + `challenges.cloudflare.com` script/frame, `connect-src http: https: ws: wss:`).

**Window creation is gated on the local backend.** `DesktopBackendPool.ts:288-302` calls `desktopWindow.handleBackendReady` → `createMainIfBackendReady` (`DesktopWindow.ts:782-788, 863-867`); macOS dock `activate` uses the same latch (`:859`, `DesktopLifecycle.ts:225-231`). No code path opens the main window without a ready backend (grep of `createMain|ensureMain|revealOrCreateMain` callers: only `DesktopApplicationMenu.ts:102`).

## 3. `DesktopAppBranding` flow

- Type: `packages/contracts/src/ipc.ts:173-185` `{ baseName: string; stageLabel: DesktopAppStageLabel; displayName: string }`, with `DesktopAppStageLabel = "Alpha" | "Dev" | "Nightly"` (`:158`, schema `:172`).
- Filled in **main**: `DesktopEnvironment.ts:88-111` — `APP_BASE_NAME` constant; stage from `isDevelopment` (= `VITE_DEV_SERVER_URL` set, `:150`) else nightly regex else "Alpha"; stored as `environment.branding` (`:224`).
- **IPC**: sync channel `desktop:get-app-branding` (`ipc/channels.ts:18`), handler `ipc/methods/window.ts:60-67` returns `environment.branding` decoded through `DesktopAppBrandingSchema`; preload `preload.ts:34-40` → `window.desktopBridge.getAppBranding()` (`contracts ipc.ts:1067`).
- **Web**: `apps/web/src/branding.ts:4-27` — injected values win; fallback `VITE_HOSTED_APP_CHANNEL` ("Latest"/"Nightly") or DEV "Dev" or "Alpha"; base fallback "T3 Code"; `formatAppDisplayName` drops the suffix only for "latest" (`branding.logic.ts:3-12`). The connected server's nightly version can re-label the stage (`branding.logic.ts:14-22`, used by `__root.tsx:213-215`, `SidebarStageBackdrop.tsx:43-51`).

**Can a Zerops build set it without touching web?** Only partly. Changing `DesktopEnvironment.ts:88` renames the document title, auth shells and pairing surface through the bridge. But: (a) a new stage label (e.g. "Beta" or none) fails the closed literal schema at the IPC boundary — contracts change required; (b) the sidebar wordmark is a hard-coded SVG, not branding-driven; (c) `index.html` title/boot splash, manifest and favicons are static files; (d) stage art only knows dev/nightly. Inferred recommendation: one brand constant in `packages/shared` consumed by `DesktopEnvironment.ts`, `branding.ts`, the build script's `resolveDesktopProductName`, and a `Wordmark` component.

## 6. Effort and risks

**Toolchain the repo requires:** Node ^24.13.1, pnpm 11.10.0 (`package.json:52-55`); Electron 41.5.0, electron-builder 26.15.6 (`apps/desktop/package.json:23,34`); **cargo** for `native/resource-monitor` (`build-desktop-artifact.ts:1746-1796`; `T3CODE_DESKTOP_REUSE_RESOURCE_MONITOR` only reuses an existing binary); macOS `sips`/iconutil for `.icns` (`:1829-1876`); Linux ImageMagick (`:629`); Windows Python/MSVS for node-gyp (`:3286-3294`). Entry: `vp run dist:desktop:dmg:arm64` etc. (`package.json:31-38`); unsigned build scrubs `CSC_*`/`APPLE_API_*` (`:3277-3284`). The existing "smoke test" is only an 8 s launch-and-grep for module errors (`apps/desktop/scripts/smoke-test.mjs:30-56`).

**S5 "one smoke build" (remote-only, unbranded), inferred:** (1) skip backend start + resource-monitor + Windows sidecar staging; (2) static renderer source for `t3code://app` and unconditional window open; (3) web bundle built in hosted-static mode with empty bootstraps; (4) hide the SSH card (`ConnectionsSettings.tsx:3125`) — the local-backend sections already disappear without a primary; (5) run the Zerops session/candidate flow (spec-z3 §4) inside the renderer. Roughly 2–4 agent-days plus toolchain setup; no signing needed for a local DMG/AppImage.

**Fully branded build, additional:** three Icon Composer projects + manual macOS export (`assets/README.md:15-32`), DMG SVGs, wordmark component, `index.html`/manifest/favicons, `DESKTOP_APP_ID`, productName/artifactName/AUMID/wmClass/dir names, contracts stage-label union, AUR packaging, a release workflow. 2–3 days plus signing enrolment.

**Risks the repo shows:** no release/publish workflow exists (`.github/workflows/ci.yml` only; `verified.md:446` lists 13 deleted upstream workflows) — the updater feed, GitHub releases and AUR all depend on one; macOS signing needs `T3CODE_APPLE_TEAM_ID` (10-char, `:1056-1060`) and, for Clerk passkeys, a provisioning profile (`:1062-1065`) — dropping Clerk removes that dependency but the single-instance lock is owned by the Clerk bridge (`DesktopClerk.ts:128-136`); Windows signing = Azure Trusted Signing env set (`:1302-1314`); notarization goes through electron-builder (`:3299`). Version convention: the push loop's `0.1.0-dev.<sha>` (`verified.md:448`) classifies as channel "latest"/stage "Alpha" (`updateChannels.ts:3`, `build-desktop-artifact.ts:2074-2080`). Renaming `userDataDirName` orphans existing state unless the legacy-path logic is extended (`DesktopAppIdentity.ts:48-67`). `verified.md:65`: `t3 serve` has no base-path flag — irrelevant to the desktop only if the local backend is gone.
