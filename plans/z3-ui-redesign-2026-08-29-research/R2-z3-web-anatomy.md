## Summary
1. The z3 web client is Tailwind v4 + Base UI + cva primitives in `apps/web/src/components/ui/*`; every colour flows through ~60 semantic CSS vars in `index.css` (light `:root` @1388, dark `@variant dark` @1451, sidebar-local palette `[data-app-sidebar]` @1494) and a contrast-derivation layer (`--contrast-*` @1874). Radius scale is `--radius: 0.625rem` (+ `--control-radius: 0.5rem`); topbar `--workspace-topbar-height: 52px` (@79-121, WCO override @124); sidebar 256px default / 208 min (`threadSidebarWidth.ts`); composer `max-w-3xl` + 22px glass shell + 16px strip (index.css 720-1290, ChatView.tsx 7078-7085).

2. Theming: a `ThemeDefinition` (58 `THEME_COLOR_ROLES`, `packages/shared/src/themePalettes.ts:18-77`) is written to `--app-theme-*` vars by `applyThemePalette` (`themePalette.ts:1854`) and mapped to semantic tokens under `html[data-theme-id]` (index.css 1552-1617). The default look ("T3 Code") is NOT a theme — it is the bare `:root` literals; `useTheme.ts` default preference is `"system"`. On web, `--primary` comes from the `messageAction` role; the `accent`/`accentForeground`/`textMuted` roles are unconsumed by index.css.

3. A Zerops built-in theme can be added with no structural change (≈6 files), but making it default and removing T3 residue touches `useTheme.ts`, `index.html` boot script, `ThemePreviewCircles.tsx`, plus 217 hard-coded Tailwind palette utilities (hotspots: `ResourceTelemetryDiagnostics.tsx` 38, `Sidebar.tsx` 34, `Sidebar.logic.ts` 32, `pullRequestPresentation.tsx` 21, `ChatMarkdown.tsx` 15, `ThreadStatusIndicators.tsx` 14), the blue AuthSurfaceShell gradient, and the provider-accent swatches (`#2563eb` first, collides with a blue/teal brand).

4. Zerops surfaces exist (landing, picker, provisioning, strip, map, cards, quick actions, settings page) and reuse `ui/*` (Button/Badge/Spinner/Input) with ad-hoc `rounded-xl border-border/55 bg-card/20` frames. The Zerops landing only renders when `isHostedStaticApp()` is true (`hostedPairing.ts:35` — `VITE_HOSTED_APP_CHANNEL` set or origin == `VITE_HOSTED_APP_URL`, default `https://app.t3.codes`) AND `environments.length === 0` (`routes/-chatIndexView.ts`); the container-served bundle has neither, so `__root.tsx` falls to `resolveInitialServerAuthGateState()` → `/pair`.

5. Mobile: `useIsMobile` = <768px sheet sidebar; composer collapses at <640px with a view-transition morph; right panel becomes a Sheet at ≤980px; dialogs become bottom sheets <640px.

## 3. Theming engine end to end

**Definition → CSS.** `ThemeDefinition` (`packages/shared/src/themePalettes.ts:79-92`: id, label, appearance, colors, variants?, collection?, sidebarArtwork?, managed?) → `applyThemePalette(theme, appearance)` (`themePalette.ts:1854-1877`) sets `html[data-theme-id]` and every role to `--app-theme-*` (`APP_THEME_VARIABLES` :1766-1824) → `index.css:1552-1617` remaps them onto the semantic tokens (`--background ← canvas`, `--primary ← messageAction`, `--accent ← accentSurface`, `--ring ← focus`, sidebar/code/terminal families) and again for `[data-app-sidebar]` @1836-1863. No theme → `data-theme-id` removed and the `:root` literals (T3 Code look) apply.

**All 58 `THEME_COLOR_ROLES`** (`themePalettes.ts:18-77`): canvas (page bg → `--background`); chrome (html/body + browser `theme-color` → `--app-chrome-background`); toolbar / toolbarForeground / toolbarBorder / toolbarControl / toolbarControlForeground / toolbarControlHover (thread header bg/text/separators/control bg/text/hover, applied @1746-1785); surface (`--card`); surfaceRaised (composer glass, banners); surfaceOverlay (`--popover` menus/dialogs); text (`--foreground`); **textMuted (web: unconsumed — no `--app-theme-text-muted` in index.css; mobile/preview only)**; border; input (input borders, dark fills); focus (`--ring`); **accent / accentForeground (web: unconsumed except `ThemeImportDialog.tsx:78` fallback; consumed by mobile)**; secondary / secondaryForeground; muted / mutedForeground; placeholder; secondaryLabel (composer chip text); iconMuted; error / errorForeground / errorSurface (+ destructive aliases); warning ×3; update ×3 (update pills); accentSurface / accentSurfaceForeground (`--accent`: hover/selected surfaces); messageSurface / messageForeground (user bubble); messageAction / messageActionForeground / messageActionHover (**`--primary` on web**: send button, CTAs, switches, sliders); codeBackground / codeForeground (code blocks, diff, file preview); sidebar / sidebarForeground / sidebarMutedForeground / sidebarControlSurface / sidebarRowHover / sidebarRowActive / sidebarRowSelected / sidebarBorder; terminalBackground / terminalForeground / terminalCursor / terminalSelection / terminalScrollbar / terminalScrollbarHover.

**Variants / halves / follow-system.** `variants.dark` or `.light` gives the other appearance (`getThemeColorsForMode` :1440). Preference storage: `t3code:theme`, `t3code:theme-appearance-mode` (light|dark|system, source of truth), legacy `t3code:theme-follow-system`, `t3code:theme-halves:v1` (a different theme per appearance, `resolveThemeHalf` :1970), custom library `t3code:themes:v1` (`hooks/useTheme.ts:33-37`, `themePalette.ts:33-36`). `resolveThemeAppearance` (:1879) picks light/dark from mode + `matchMedia('(prefers-color-scheme: dark)')` + halves; `applyTheme` toggles `.dark` and calls `syncBrowserChromeTheme` (meta theme-color) and `syncDesktopTheme` (Electron `setTheme`). **Default:** `DEFAULT_THEME_SNAPSHOT = { theme: "system", followSystem: true, appearanceMode: "system" }` (`useTheme.ts:39-45`) — i.e. stock look, OS-driven dark/light. `index.html:12-395` duplicates the whole resolution (built-in palette copy `BUILT_IN_THEME_PALETTES`, `RESERVED_THEME_IDS`, halves) to paint before React.

**Contrast slider** (`appearanceContrast.ts`): writes `--appearance-contrast-base` (min(c,100)%), `--appearance-contrast-boost` (c-100)%, `--appearance-contrast-border-boost` ((c-100)/4)%; `index.css:1874-1986` derives every `--contrast-*` role (foreground, muted, placeholder, borders, sidebar, toolbar, message) by `color-mix` toward `--appearance-contrast-target` (black/white). ## 7. Performance constraints to respect

`AGENTS.md` ("Performance without compromise", "Taste"): no continuously repainting animations (they peg GPUs on high-refresh displays); watch websocket payload size; lists must stay cheap to render; hit every surface (web/desktop/mobile, Settings, palette, keybindings). Existing conventions in `index.css`: duty-cycled, `steps()`-timed keyframes `status-pulse`, `ghost-pulse`, `status-ping`, transform-only `skeleton` (@145-268, comments quantify 14 vs 288 updates/cycle on 120 Hz); `live-activity-focus` uses `will-change: transform` and is disabled under `prefers-reduced-motion` (@461-515); grain is baked into each surface background rather than a fixed overlay (@2020-2047); theme switches suppress transitions (`.no-transitions` @1381, `data-theme-token-probe` @1672); `prefers-reduced-motion` blocks @2513. Timeline is virtualized (`@legendapp/list`), diffs run in a worker pool (`DiffWorkerPoolProvider`), terminal is libghostty. A Zerops restyle must keep glass (`backdrop-filter`) usage to the existing utilities and avoid animated gradients (the Zerops GUI's chart/gradient tiles would need static rendering).
