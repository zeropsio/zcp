# S5 — desktop remote-only, mobile catch-up, activity relay on Zerops — plan

Status: plan v2, 2026-08-29 (Codex second opinion folded in — §1a). Inputs: brief §6 S5, owner decisions 2026-08-28 (Zerops-only; desktop + mobile kept;
activity relay kept and hosted by us; T3 cloud *reach* deleted after S5), the S5 surface map
(`scratchpad/s5-map.md`, 495 lines; file:line below). Home after landing: `docs/spec-z3.md §8` (S5) + ledger;
this plan is deleted.

## 0. Shape

Desktop becomes a **pure hosted client in an Electron shell**: it ships the web bundle built in `hosted-static`
mode (the mode that already renders the Zerops landing → picker → identity connect) and serves it from disk;
the local backend, WSL, SSH launch and Clerk go. Mobile gets the same Zerops sign-in + picker on top of the
shared client runtime, with the pairing screen kept as a fallback. The activity relay (push, Live Activities)
is re-shelled from a Cloudflare Worker into a Node service on Zerops with Postgres, its Clerk auth replaced by
Zerops-token verification; T3 Connect's reach/pairing API groups are deleted with it.

## 1a. Codex corrections (2026-08-29), applied

| Finding | Applied as |
|---|---|
| Desktop couples to the local backend beyond the two named edges: `ipc/methods/window.ts:24` imports the backend pool, local auth and WSL; bootstrap/token IPC and `pickFolder` (path-returning dialogs return laptop paths meaningless in Zerops); project favicons/paths; preview's discovered `localhost` ports intentionally fail on public origins (`browser/browserTargetResolver.ts:166`). | **D1/D2 widened**: S5-1 audits `preload.ts`, the IPC contract, Settings controls and every path-returning dialog; `window.ts` rewritten without backend/WSL/local-auth; folder/file pickers removed (no laptop paths in a Zerops product); preview kept for explicit public URLs only. |
| D6 unsound: the link proof (`cloud/http.ts:376`) carries a random environment id, a self-generated key and a self-signed descriptor — no Zerops project; a project id merely signed by the environment is not attestation. D5 deletes `RelayClientGroup` but D7 needs its challenge/link endpoints. | **D6/D7 corrected**: the proof gains `zeropsProjectId` + the service/endpoint identity (the container's `T3CODE_ZEROPS_PROJECT_ID` and its public origin); the relay verifies the presented Zerops token's membership of THAT project against the Zerops API and that the endpoint belongs to a service of that project (`GET /project/{id}/service-stack`); the handshake stays client-mediated (binds user intent + token + challenge + environment). The challenge/link endpoints survive as a smaller `RelayLinkGroup`; the rest of `RelayClientGroup` + `RelayDpopClientGroup` go. |
| A DB-backed queue is acceptable only with explicit durable semantics. | **D5 corrected**: job table with unique `jobId`, insert committed before the publish request is acknowledged, `availableAt`, atomic lease via `SELECT … FOR UPDATE SKIP LOCKED`, lease expiry + recovery, 5 retries with backoff, job expiry, dead-letter state; one worker loop per replica. |
| `client-runtime` is the right layer, but `firstPrompt.ts:55` uses `window.localStorage` and `containerHealth` assumes browser `fetch`/CORS/manual redirects. | **D3 corrected**: storage and fetch are injected adapters; React-Native behaviour of the health probe gets a test (no `redirect:"manual"` semantics on RN). |
| S5-4 is not independent of S5-2/3: mobile relay state, `CloudSession` and the root `CloudAuthProvider` are Clerk-shaped. | **S5-4 split**: S5-4a relay server + deployment (independent); S5-4b client integration (server link handshake with Zerops token, mobile registration on the Zerops session) after S5-2/3. |
| Owner acceptance fails before mobile compiles: full Xcode not selected, CocoaPods absent (`docs/ios-build-brief.md:14`); EAS still targets upstream. | **§3 preflight** for the owner's Mac added; EAS config retargeted or left unused (personal-team local build is the route). |

## 3. Acceptance
- Desktop: hosted landing → thread on `z3-eval`; no process spawned by the app besides Electron; updater points at `krls2020/z3`.
- Mobile: sign-in → picker → thread, no code typed (owner's iPhone); pairing fallback still works.
- Relay: running on Zerops with Postgres; Zerops-token-authenticated device registration; publish from a container persisted; no Cloudflare/Clerk/PlanetScale/Axiom references left in `infra/relay`.
- Owner preflight (Mac): `sudo xcode-select -s /Applications/Xcode.app`, `brew install cocoapods`; an unsigned desktop DMG will be challenged by Gatekeeper (right-click → Open).
