# Slice brief: S2 — Downstream bundle, authoring, and console parity

Self-contained: no other plan file is required to execute this. The cited spec
sections are the authority for behavior.

**Outcome** (observable): export/launch and recipe/port authoring preserve
`local-storage:single@1` without HA, DB profile, or connection-env semantics;
`run.volume.hostname` counts as a managed dependency reference; Data Console
classifies Local Storage as unsupported file storage rather than unknown.

**Protocol**: RED → GREEN → REFACTOR.
1. Write one named test first and confirm it fails for the intended assertion:
   `go test ./internal/ops/bundle ./internal/tools ./internal/authoring/recipe ./internal/authoring/port ./internal/dataconsole/console/provider -run 'LocalStorage' -short -count=1 -v`
2. Implement only enough for that test to pass; repeat one test at a time.
3. Refactor with tests green; rerun the command and then `make lint-fast`.

**BUILD addendum**
- Never batch-write tests: RED → GREEN → REFACTOR one named test at a time.
- Independent oracle: expected YAML/type/family values are literal contract
  values, never recomputed with the implementation under test.
- Assert on public bundle builders, launch readiness output, emitted import
  YAML, port harden plan, and Data Console registry derivations only.
- Use table-driven `Test{Op}_{Scenario}_{Result}` naming and report one
  layer-matrix pass line per touched CLAUDE.md layer.
- `make lint-fast` must be clean before reporting done.

**Report contract** (all required — never summarize away a failure)
- RED output + exit code for every named test
- GREEN output + exit code
- Files touched (exact list)
- Layer-matrix pass lines (unit, integration, tool)
- Independent-oracle note for exact type, absence of HA/profile, and file family

**Stop conditions**: scope drift; a need for an actual Local Storage console
provider; evidence that `run.volume.hostname` is not the platform mount
reference; acceptance-criteria change; repeated unexplained check failure.
