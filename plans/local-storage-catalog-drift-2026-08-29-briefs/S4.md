# Slice brief: S4 — Strict authenticated schema-drift CI

Self-contained: no other plan file is required to execute this. The cited spec
section is the authority for behavior.

**Outcome** (observable): local `zcp schema check` keeps its skip-compatible
behavior, while `zcp schema check --strict` fails on missing/invalid auth or an
upstream error; the scheduled/manual GitHub workflow supplies a dedicated
environment secret and cannot report success via `SKIP`.

**Allowed scope**
- Files: `cmd/zcp/schema.go`, `cmd/zcp/schema_test.go`, `.github/workflows/schema-drift.yml`
- Explicitly excluded: creating/rotating a credential; reading personal zcli
  auth in CI; pull-request triggers; release workflow changes; schema generation.

**Spec citations**: `docs/schema-integration.md` §Schema freshness and
authenticated drift policy.

**RED test list**
- `TestSchemaCheck_StrictMissingAuthentication_ReturnsFailure` — layer: unit
- `TestSchemaCheck_StrictUpstreamFailure_ReturnsFailure` — layer: unit
- `TestSchemaCheck_NonStrictMissingAuthentication_RemainsSkipSuccess` — layer: unit
- `TestSchemaCheck_Drift_ReturnsTwoInBothModes` — layer: unit
- `TestSchemaDriftWorkflow_MainOnlyUsesEnvironmentSecretAndStrictMode` — layer: unit

**Protocol**: RED → GREEN → REFACTOR.
1. Add one named test at a time using injected credential/check seams and
   confirm the intended assertion fails:
   `go test ./cmd/zcp -run 'SchemaCheck|SchemaDriftWorkflow' -count=1 -v`
2. Implement only enough for that test. Strict exit contract: clean `0`, drift
   `2`, missing/invalid auth or fetch error `1`; non-strict keeps current skip
   success for auth/fetch failures.
3. Refactor with tests green; rerun the command and then `make lint-fast`.

**BUILD addendum**
- Never batch-write tests: RED → GREEN → REFACTOR one named test at a time.
- Independent oracle: exit codes, secret name, triggers, and permissions are
  literal policy expectations, not derived from the implementation.
- Assert on the command runner's exit/output seam and parsed workflow text;
  never call live Zerops or GitHub from unit tests.
- Use table-driven `Test{Op}_{Scenario}_{Result}` naming and report one
  layer-matrix pass line per touched CLAUDE.md layer.
- `make lint-fast` must be clean before reporting done.

**Report contract** (all required — never summarize away a failure)
- RED output + exit code for every named test
- GREEN output + exit code
- Files touched (exact list)
- Layer-matrix pass line (unit)
- Independent-oracle note; confirm no secret value is present in repo/output
- Operator-gate note: GitHub Environment `schema-drift` must restrict deployment
  branches/tags to `main`; this external setting is manually verified and is
  not claimed as unit-test evidence. The workflow also enforces
  `github.ref == 'refs/heads/main'` in-repo.

**Stop conditions**: scope drift; a need to expose a secret to PR code; any
credential value appears in output/diff; acceptance-criteria change; repeated
unexplained check failure.

**Definition of Done**
- [ ] RED replay fails at slice base and passes at slice head
- [ ] Named tests pass with `-count=1 -v`
- [ ] `make lint-fast` clean
- [ ] No file outside Allowed scope touched
- [ ] Report contract filled in full
